# Credit Risk Telegram Bot

Модель кредитного скоринга на данных соревнования Home Credit Default Risk (Kaggle) и Telegram-бот, который по заявке клиента оценивает вероятность дефолта.

## Данные

В `application_train.csv` 307 511 заявок, дефолтов среди них 8,07%: на одного дефолтника приходится 11 хороших клиентов. Кроме анкеты, в датасете есть таблицы с кредитной историей, все они связаны с анкетой по `SK_ID_CURR`:

| таблица | что в ней |
|---|---|
| `bureau`, `bureau_balance` | кредиты в других банках по данным кредитного бюро и их помесячные статусы |
| `previous_application` | прошлые заявки клиента в Home Credit |
| `installments_payments` | платежи по прошлым кредитам: срок, фактическая дата, сумма |
| `POS_CASH_balance`, `credit_card_balance` | помесячные снимки потребкредитов и кредитных карт |

## Модель

CatBoost. Категориальные признаки передаются в модель как есть, без one-hot, а пропуски в числовых признаках не заполняются: CatBoost обрабатывает их сам.

Всего признаков 170. Из анкеты берутся 62: 47 исходных полей и 15 производных (возраст, отношение кредита к доходу и к цене товара, среднее внешних скоринговых оценок и т.д.). Остальные 108 получены из таблиц истории. Каждая таблица сворачивается через `groupby` в одну строку на клиента: сколько у него кредитов, какая доля долга не погашена, какой была максимальная просрочка, как часто банк отказывал ему раньше, сколько платежей он внёс с опозданием за последний год.

### Как проверяли

20% данных отложены как тест и не участвовали ни в одном эксперименте. Эксперименты сравнивались на стратифицированной кросс-валидации по обучающей части, 5 фолдов. Фолды во всех экспериментах одинаковые, поэтому варианты можно сравнивать пофолдово. Метрики: Gini, PR-AUC, KS и стоимость ошибок на 100 заявок. Результаты по фолдам лежат в `reports/`.

| эксперимент | Gini (CV) |
|---|---|
| исходная предобработка: медианы, винсоризация, one-hot | 0,513 |
| пропуски без заполнения, категории как есть | 0,515 |
| + кредитное бюро | 0,533 |
| + прошлые заявки | 0,549 |
| + история платежей | 0,563 |
| + POS-кредиты и кредитные карты | 0,567 |
| + подбор гиперпараметров (Optuna, 40 попыток) | 0,569 |

Весь прирост дала кредитная история. Веса классов, способ заполнения пропусков и кодирование категорий на ранжирование почти не влияли. Подбор гиперпараметров добавил 0,002 Gini, но стоимость ошибок при этом немного выросла, поэтому в финальной модели оставлены параметры по умолчанию: 500 итераций, глубина 6, learning rate 0,05.

На отложенном тесте:

| модель | Gini | ROC-AUC | стоимость ошибок на 100 заявок |
|---|---|---|---|
| только анкета | 0,532 | 0,766 | 33,44 |
| анкета + кредитная история | 0,581 | 0,790 | 31,89 |

### Порог

Веса классов в модели не используются: ранжирование они не улучшали, а вероятности искажали. Модель выдаёт откалиброванную вероятность дефолта (на тесте средняя предсказанная вероятность 0,0802 при фактической доле дефолтов 0,0807), а решение принимается порогом.

Порог выбран по стоимости ошибок. Считаем, что пропустить дефолтника в 5 раз дороже, чем отказать хорошему клиенту. Тогда отказывать выгодно, когда вероятность дефолта выше 1 / (1 + 5) ≈ 16,7%.

При этом пороге на тесте модель отклоняет 12% заявок и ловит 42% дефолтников, из отклонённых 28,5% действительно не вернули бы кредит. Precision от 25% держится примерно до recall 50%. Чтобы поймать 75% дефолтников, пришлось бы отклонять треть всех заявок.

### Интерпретация

SHAP-значения считаются встроенными средствами CatBoost. На кредитную историю приходится около 47% решений модели. Самый сильный признак из анкеты: среднее внешних скоринговых оценок (`EXT_SOURCE_MEAN`). Из истории сильнее всего работают доля непогашенного долга по кредитам в других банках и превышение выданной суммы над запрошенной.

У модели есть ограничение: пол клиента (`CODE_GENDER`) стоит на втором месте по важности. Во многих юрисдикциях учитывать пол в кредитных решениях запрещено, поэтому для реального применения модель нужно переобучить без него.

## Бот

Бот принимает JSON с одним клиентом или CSV с несколькими. В данных должны быть 62 признака анкеты (их список выводит команда `/features`) и `SK_ID_CURR`.

По `SK_ID_CURR` бот ищет клиента в таблице кредитной истории `data/history_features.parquet`. В ней заранее посчитанные агрегаты для 354 тысяч клиентов датасета. Если клиент найден, решение принимает основная модель. Если нет, бот использует резервную модель, обученную только на анкете. Основная модель с пустой историей на тесте даёт Gini 0,511 и занижает вероятности, резервная даёт 0,532 и откалибрована. Порог у обеих моделей один.

Пример ответа:

```text
Предсказание: Низкий риск дефолта
Вероятность дефолта: 5.30%
Порог отказа: 16.7%
Модель: основная, с кредитной историей
```

На CSV бот отвечает файлом с колонками `PREDICTION`, `DEFAULT_PROBABILITY`, `HISTORY_FOUND`, `MODEL_USED` и `RISK_LABEL`.

Признаки бот ждёт в том виде, в каком они получаются после предобработки в ноутбуке, вместе с производными. Считать производные признаки из исходных полей анкеты бот пока не умеет.

## Запуск

```bash
pip install -r requirements.txt
```

Данные скачиваются через `kagglehub` в первых ячейках ноутбука. Путь к ним прописан в ноутбуке явно, его нужно заменить на свой.

Затем нужно прогнать `notebooks/Credit-Scoring-Analysis.ipynb` до раздела «Организация файлов для бота» включительно. Ячейка сохранения записывает обе модели в `models/`, а таблицу истории в `data/`. Таблица весит около 80 МБ и в git не хранится, так что без этого шага бот не запустится. Ячейки с кросс-валидацией и Optuna для этого перезапускать не нужно.

Токен бота задаётся в `.env` в корне проекта:

```text
BOT_TOKEN=...
```

Бот запускается из корня проекта:

```bash
python -m source.bot
```

## Структура проекта

```text
notebooks/   — EDA, эксперименты, финальная модель, SHAP
source/      — код бота и инференса
models/      — основная и резервная модели, списки признаков, порог
data/        — кэш агрегатов и таблица кредитной истории (не в git)
examples/    — примеры входных данных для бота
reports/     — метрики экспериментов по фолдам, сравнение на тесте, результаты Optuna
```
